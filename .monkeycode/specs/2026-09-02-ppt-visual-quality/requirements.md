# PPT 视觉质量优化需求文档

Feature Name: ppt-visual-quality
Updated: 2026-09-05

## 简介

本功能提升 AI PPT 在商务汇报、数据报告、产品路演、学术报告和教育培训等场景中的内容结构、视觉一致性与交付稳定性。用户先审阅可编辑大纲，再选择标准模式或精修模式生成演示文稿；系统在交付前执行可量化的视觉质检，并对可修复问题自动重排。

## 术语

- **PPT 系统**：从主题或上传材料生成大纲、演示文稿和质量报告的现有服务。
- **大纲草稿**：包含页面顺序、页面类型、页面标题、核心结论、内容块和素材意图的可编辑结构。
- **页面类型**：表达页面语义目的的分类，包括封面、目录、章节、要点、图文、数据、对比、时间线、流程、总结和结束页。
- **设计令牌**：控制颜色、字体、字号、间距、圆角、线条、图表和装饰的统一参数集合。
- **标准模式**：使用确定性规则完成布局、内容密度控制、质检和自动重排的生成模式。
- **精修模式**：在标准模式基础上增加逐页预览和视觉模型复审的生成模式。
- **质量报告**：记录每页质量分、问题类型、修复动作和最终状态的结构化结果。
- **自动重排**：系统调整页面布局、内容拆分、字号、间距或素材裁切以解决质量问题的过程。
- **最终总页数**：交付演示文稿中的全部页面数量，包含系统生成的封面和用户审阅的内容页。

## 需求

### 需求 1：先审大纲

**用户故事：** 作为 PPT 创建者，我希望在渲染前审阅故事线和页面结构，从而控制演示逻辑与内容重点。

#### 验收标准

1. WHEN 用户提交主题或材料，PPT 系统应生成包含页面类型、标题、核心结论、内容块和素材意图的大纲草稿。
2. WHILE 大纲草稿处于编辑状态，PPT 系统应允许用户新增、删除、重排和修改页面。
3. WHEN 用户批准大纲草稿，PPT 系统应锁定一个带版本号的大纲快照并使用该快照创建生成任务。
4. WHEN 用户修改已批准的大纲草稿，PPT 系统应创建新版本并要求用户重新批准。
5. IF 大纲草稿缺少标题、核心结论或有效内容块，PPT 系统应标记对应页面并阻止批准操作。
6. WHEN 用户选择最终总页数 N，PPT 系统应生成 N-1 个可编辑内容页并在交付时生成 1 个封面页。
7. WHEN 用户新增或删除大纲内容页，PPT 系统应将预计最终总页数更新为当前内容页数量加 1。

### 需求 2：场景与模板适配

**用户故事：** 作为不同场景的 PPT 创建者，我希望系统根据演示目的匹配视觉表达，从而获得符合语境的结果。

#### 验收标准

1. WHEN PPT 系统生成大纲草稿，PPT 系统应将演示识别为商务汇报、数据报告、产品路演、学术报告、教育培训或通用演示中的一种场景。
2. WHEN 用户选择场景，PPT 系统应展示至少三个适用于该场景的模板候选及配色预览。
3. WHEN 用户选择模板，PPT 系统应在全部页面应用同一套设计令牌。
4. WHEN 页面包含数据、对比、时间关系或流程关系，PPT 系统应选择表达对应关系的页面类型。
5. IF 场景识别置信度低于 0.60，PPT 系统应使用通用演示场景并允许用户调整。
6. WHEN PPT 系统渲染演示文稿，PPT 系统应将所选模板的设计令牌应用到实际颜色、字体和背景样式。

### 需求 3：内容密度控制

**用户故事：** 作为演示者，我希望每页只表达一个清晰结论，从而让观众快速理解重点。

#### 验收标准

1. WHEN PPT 系统构建页面内容，PPT 系统应为每页保留一个核心结论。
2. WHEN PPT 系统构建页面内容，PPT 系统应为每个非封面页面提供核心论点、依据或例子、行动建议和衡量指标内容块。
3. WHEN 正文内容超过页面类型的容量预算，PPT 系统应优先拆分页面并保持原始内容顺序。
4. WHEN 页面使用项目列表，PPT 系统应将一级项目数量控制在 3 至 6 项。
5. WHEN 自动调整正文字号，PPT 系统应保持正文字号不低于 14 磅且标题字号不低于 24 磅。
6. IF 内容拆分会导致总页数超过用户页数上限，PPT 系统应返回超限页面和精简建议供用户确认。
7. WHEN 相邻页面表达不同叙事角色，PPT 系统应为页面提供不同类型的论据结构，例如趋势证据、对比判断、案例拆解、优先级取舍或阶段门槛。
8. WHEN PPT 系统生成默认大纲，PPT 系统应使相邻内容页的论据文本、论据类型和指标组合产生可识别差异。

### 需求 4：语义布局与视觉层级

**用户故事：** 作为 PPT 创建者，我希望版式跟随内容关系变化，从而避免重复和机械的页面观感。

#### 验收标准

1. WHEN PPT 系统渲染页面，PPT 系统应从封面、目录、章节、要点、图文、数据、对比、时间线、流程、总结和结束页中选择页面类型。
2. WHEN 连续页面具有可替换布局，PPT 系统应限制相同布局连续出现不超过 2 页。
3. WHEN 页面包含标题、核心结论和辅助内容，PPT 系统应通过字号、字重、颜色或空间建立三级视觉层级。
4. WHEN 页面包含对齐的多个内容块，PPT 系统应使用统一网格和间距令牌定位内容块。
5. IF 页面类型与内容结构不兼容，PPT 系统应选择兼容页面类型并在质量报告中记录调整原因。

### 需求 5：图片与图表质量

**用户故事：** 作为演示者，我希望素材服务于页面结论，从而增强信息表达和专业感。

#### 验收标准

1. WHEN 页面需要图片，PPT 系统应根据页面核心结论生成素材描述和搜索关键词。
2. WHEN 页面声明素材意图，PPT 系统应将可用图片或模板视觉元素放置到页面中，并保留图片与页面结论的关联信息。
3. WHEN PPT 系统放置图片，PPT 系统应保持图片原始宽高比，裁切后的主体区域应位于可见画布内。
4. WHEN 页面包含结构化数值数据，PPT 系统应使用与比较关系匹配的图表类型并显示数据来源占位信息。
5. WHEN 多页使用同类图片，PPT 系统应保持统一的色调、圆角、描边和裁切策略。
6. IF 素材获取失败，PPT 系统应使用模板内置视觉元素完成页面并在质量报告中标记素材状态。
7. WHEN PPT 系统渲染连续内容页，PPT 系统应从至少五种构图骨架中选择兼容页面，包括大数字证据、双栏对比、卡片矩阵、横向路线图和图文叙事。
8. WHEN 页面使用图片或视觉元素，PPT 系统应根据页面语义选择图片比例、裁切位置和视觉焦点。

### 需求 6：质量模式选择

**用户故事：** 作为 PPT 创建者，我希望在生成速度和视觉精度之间自主选择，从而匹配当前交付场景。

#### 验收标准

1. WHEN 用户批准大纲草稿，PPT 系统应提供标准模式和精修模式选项，并展示预计处理差异。
2. WHEN 用户选择标准模式，PPT 系统应执行规则质检和自动重排。
3. WHEN 用户选择精修模式，PPT 系统应执行规则质检、逐页预览、视觉模型复审和自动重排。
4. WHEN PPT 系统创建生成任务，PPT 系统应保存用户选择的质量模式。
5. IF 精修阶段服务不可用，PPT 系统应完成标准模式处理并在质量报告中记录降级状态。

### 需求 7：自动质检与重排

**用户故事：** 作为 PPT 创建者，我希望系统在交付前自动发现和修复视觉问题，从而减少人工返工。

#### 验收标准

1. WHEN 页面完成首次渲染，PPT 系统应检查文本溢出、元素重叠、对比度、内容密度、图片变形和布局重复。
2. WHEN 文本框内容超出边界，PPT 系统应通过内容拆分、布局切换或字号调整解决溢出，并满足字号下限。
3. WHEN 非装饰元素重叠面积超过较小元素面积的 2%，PPT 系统应重新定位元素。
4. WHEN 正文文本与背景的对比度低于 4.5:1，PPT 系统应调整文本色或背景色。
5. WHEN 图片显示宽高比与原图宽高比偏差超过 2%，PPT 系统应调整为等比裁切或等比缩放。
6. WHILE 页面仍存在可自动修复问题，PPT 系统应执行最多 2 次自动重排。
7. IF 页面经过 2 次自动重排仍存在严重问题，PPT 系统应标记页面为需人工复核并继续生成其他页面。

### 需求 8：质量结果与可追踪性

**用户故事：** 作为 PPT 创建者，我希望查看生成质量和修复记录，从而快速定位需要人工调整的页面。

#### 验收标准

1. WHEN 生成任务完成，PPT 系统应提供整体质量分、逐页质量分、问题列表和修复动作。
2. WHEN 页面包含严重问题，PPT 系统应在预览页突出显示对应页码和问题类型。
3. WHEN 用户下载演示文稿，PPT 系统应同时保留质量模式、大纲版本、模板版本和质量报告版本。
4. WHEN 用户重新生成指定页面，PPT 系统应保留未选页面并创建新的质量报告版本。
5. IF 质量报告生成失败，PPT 系统应保留演示文稿产物并显示报告状态。

### 需求 9：性能与任务反馈

**用户故事：** 作为 PPT 创建者，我希望了解生成进度和额外质量处理成本，从而合理安排等待时间。

#### 验收标准

1. WHEN 任务进入大纲、素材、渲染、质检、重排或交付阶段，PPT 系统应向用户发布阶段名称和完成进度。
2. WHEN 用户选择质量模式，PPT 系统应在创建任务前展示该模式包含的处理阶段。
3. WHILE 标准模式执行，PPT 系统应在单页质检完成后释放对应预览资源。
4. WHILE 精修模式执行，PPT 系统应限制并发视觉复审数量并保持任务状态可恢复。
5. IF 用户取消生成任务，PPT 系统应停止后续处理并将已完成阶段保存到任务记录。

## INCOSE 质量检查

- 每条验收标准均指定明确主体、触发条件和可测试响应。
- 需求统一使用“大纲草稿”“页面类型”“质量模式”“质量报告”等术语。
- 每条验收标准聚焦单一行为，并为阈值、次数、页数和对比度提供量化条件。
- 需求描述聚焦产品行为，具体模块、存储和接口安排放入技术设计。
