# 网页 Agent 本地 Agent Host SSD 需求文档

## 1. 引言

本规格定义 CodingMatrix Web Agent 工作台与 VS Code Agent 工作台的产品边界、交互契约和验收要求。两个工作台共享 Agent 会话、模型、Skills、任务和策略；VS Code 工作台通过扩展原生能力访问授权工作区、执行本地工具、采集诊断和回传结果。

本地验证是 Agent 工具链的一部分。用户在当前工作台完成 Agent 操作、策略控制和结果查看，云端保持会话状态一致，VS Code 扩展在本地提供原生工具能力。

## 2. 术语表

- **Web Agent 工作台**：运行在浏览器中的 CodingMatrix Agent 工作台，适合跨设备、远程项目和团队协作。
- **VS Code Agent 工作台**：由 VS Code Webview 与扩展原生 API 组成的 Agent 工作台，适合本地代码编辑和验证。
- **扩展**：运行在 VS Code 中的 CodingMatrix Agent Host 扩展，提供本地工具和验证能力。
- **云端**：CodingMatrix FastAPI 服务及其 Agent、StateGraph、模型和 Skill 服务。
- **Agent Host**：在本地工作区执行 Agent 工具动作并向网页端回传事件的插件运行时。
- **验证动作**：云端写入 `State.pending_actions`、等待插件执行的结构化任务。
- **工具动作**：Agent 请求 Agent Host 执行的文件、终端、诊断、验证或 Skill 动作。
- **会话策略**：网页端为 Agent 会话配置的模型、Skills、自动执行和权限规则。
- **本地验证范围**：`local_runtime` 或 `local_e2e`。
- **云端验证范围**：`cloud_syntax`，表示云端基础语法和结构检查。
- **验证结果**：插件对验证动作生成的脱敏结构化结果。
- **任务版本**：由 `task_id` 和 `revision` 标识的状态版本。
- **用户项目**：用户在本地工作区中授权给插件访问的项目目录。

## 3. 用户角色

- **项目开发者**：在 VS Code 中授权工作区、查看验证动作和执行结果。
- **云端 Agent**：生成验证计划、创建本地验证动作和聚合验证结果。
- **平台管理员**：配置云端验证范围和插件兼容策略。
- **Agent 会话用户**：在任一 Agent 工作台发起任务、选择模型、控制 Skills 和审批本地动作。

## 4. 需求

### 需求 1：工作区授权

**用户故事：** 作为项目开发者，我希望明确授权本地项目工作区，使插件仅在授权范围内执行验证。

#### 验收标准

1. 当插件首次访问工作区时，插件应请求项目开发者确认工作区路径和访问范围。
2. 当项目开发者确认工作区后，插件应保存当前工作区标识，并将工作区标识关联到后续验证结果。
3. 当验证动作引用授权工作区之外的路径时，插件应将动作标记为 `rejected`，并返回结构化路径原因。
4. 当项目开发者撤销工作区授权时，插件应停止该工作区的待执行动作，并清除本地授权状态。

### 需求 2：验证动作接收

**用户故事：** 作为云端 Agent，我希望向插件发送带版本信息的验证动作，使插件可以执行与当前项目状态匹配的本地任务。

#### 验收标准

1. 当云端产生 `local_runtime` 或 `local_e2e` 验证动作时，插件应接收动作的 `task_id`、`session_id`、`revision`、`schema_version`、`validation_scope`、工作区标识和执行参数。
2. 当插件接收到不支持的 `schema_version` 或 `validation_scope` 时，插件应返回结构化的 `unsupported_contract` 结果。
3. 当插件接收到重复的 `event_id` 或已完成的任务版本时，插件应返回已有处理状态，并保持一次执行语义。
4. 当插件无法确认工作区或任务版本时，插件应将动作置为 `waiting_for_confirmation`，并向项目开发者展示原因。

### 需求 3：本地验证执行

**用户故事：** 作为项目开发者，我希望插件在本地真实项目环境中执行验证，使结果反映本地依赖和服务条件。

#### 验收标准

1. 当项目开发者批准 `local_runtime` 动作时，插件应按动作声明执行依赖检查、项目构建、单元测试或本地服务检查。
2. 当项目开发者批准 `local_e2e` 动作时，插件应按动作声明执行端到端测试，并记录测试框架、命令摘要和退出状态。
3. 当本地命令超过动作声明的超时时间时，插件应终止该命令，并返回 `timeout` 状态、已执行时长和脱敏诊断摘要。
4. 当本地验证命令返回非零状态时，插件应返回 `failed` 状态、退出码、失败摘要和可定位的文件或测试信息。
5. 当本地验证命令成功完成时，插件应返回 `passed` 状态，并记录验证范围、执行环境摘要和结果时间戳。

### 需求 4：敏感信息保护

**用户故事：** 作为项目开发者，我希望验证结果保护本地密钥和敏感环境信息，使云端只获得完成验证所需的信息。

#### 验收标准

1. 当插件采集命令输出、环境变量或错误信息时，插件应在上传前过滤密钥、令牌、密码、Cookie 和完整环境变量内容。
2. 当插件生成验证结果时，插件应上传摘要、hash、退出码、测试统计和诊断位置等必要信息。
3. 当插件发现结果中包含未脱敏的敏感字段时，插件应阻止结果上传，并记录本地脱敏失败原因。
4. 当云端请求执行参数包含工作区外路径、未授权网络目标或高风险命令时，插件应要求项目开发者确认并记录拒绝原因。

### 需求 5：结果回传与状态合并

**用户故事：** 作为云端 StateGraph，我希望可靠接收插件结果并合并到正确的任务版本，使最终状态可追溯且具备幂等性。

#### 验收标准

1. 当插件完成验证动作时，插件应回传 `task_id`、`session_id`、`revision`、`schema_version`、`validation_scope`、`source=local`、状态和结果摘要。
2. 当云端收到与当前 `revision` 不匹配的结果时，云端应拒绝状态合并，并返回 `revision_conflict`。
3. 当云端收到相同 `event_id` 的重复结果时，云端应保持一次状态变更，并返回幂等处理结果。
4. 当一个任务包含多个本地验证范围时，云端应在全部必需范围完成前保持 `waiting_local_validation` 状态。
5. 当所有必需验证范围通过时，云端应将任务推进到 `completed`；当任一必需范围失败时，云端应将任务推进到 `failed` 或 `partial_success`。

### 需求 6：用户交互与可观测性

**用户故事：** 作为项目开发者，我希望看到验证动作、授权请求、执行进度和结果，使本地验证过程可控。

#### 验收标准

1. 当插件收到待执行动作时，插件应在 VS Code 中展示任务名称、验证范围、目标工作区和预计影响。
2. 当验证正在执行时，插件应展示开始时间、当前阶段、已用时和可取消操作。
3. 当验证结束时，插件应展示通过、失败、超时、拒绝或等待确认状态，并提供诊断摘要。
4. 当插件连接云端失败时，插件应保留未回传结果的本地状态，并在连接恢复后按任务版本继续回传。

### 需求 7：兼容性与升级

**用户故事：** 作为平台管理员，我希望插件和云端契约能够受控升级，使历史任务保持可解释。

#### 验收标准

1. 当插件启动时，插件应检查云端支持的协议版本和插件自身版本。
2. 当协议版本不兼容时，插件应停止创建新的验证执行，并展示升级指引。
3. 当插件读取旧版本验证动作时，插件应根据声明的迁移规则转换可兼容字段或返回结构化升级错误。
4. 当插件升级后恢复未完成任务时，插件应保留原始 `task_id`、`revision` 和 `event_id`。

### 需求 8：统一 Agent 会话控制

**用户故事：** 作为 Agent 会话用户，我希望在 Web 或 VS Code 工作台持续控制 Agent 任务，使对话、本地执行和验证保持在同一个会话中。

#### 验收标准

1. 当用户在任一 Agent 工作台创建 Agent 会话时，云端应为会话生成唯一的 `session_id`，并允许工作台声明对应项目和工作区。
2. 当 Agent 产生需要本地能力的工具动作时，云端应将动作关联到 `session_id`、`task_id` 和 `revision`。
3. 当扩展执行工具动作时，扩展应持续回传动作状态、进度、日志摘要和结果事件，当前工作台应在同一会话中展示这些事件。
4. 当用户在任一 Agent 工作台暂停、取消或继续 Agent 任务时，云端应向当前会话的执行端发送对应的会话控制动作。

### 需求 9：本地 Agent Host 工具能力

**用户故事：** 作为 Agent 会话用户，我希望网页 Agent 可以使用本地工作区能力，使 Agent 能够完成修改、验证和问题修复闭环。

#### 验收标准

1. 当云端请求读取工作区文件时，插件应在授权范围内返回文件元数据或经过策略过滤的内容。
2. 当云端请求修改工作区文件时，插件应执行带版本校验的文件变更，并回传变更摘要和 hash。
3. 当云端请求执行终端动作时，插件应按照会话策略执行参数化命令，并回传退出码、输出摘要和诊断。
4. 当云端请求采集 VS Code 诊断时，插件应回传 Problems、编译器和测试框架产生的结构化诊断。
5. 当工具动作完成时，网页端 Agent 应能够基于结果继续计划、修复或请求用户决策。

### 需求 10：模型接入与会话模型策略

**用户故事：** 作为 Agent 会话用户，我希望在任一 Agent 工作台接入和切换模型，使 Agent 使用符合项目需求的模型完成任务。

#### 验收标准

1. 当用户在任一 Agent 工作台添加模型供应商时，系统应保存供应商名称、协议、Base URL、凭据引用和可用模型列表。
2. 当用户测试模型连接时，系统应返回连接状态、模型能力和可诊断错误信息。
3. 当用户为会话选择模型时，云端应将模型标识和能力策略绑定到 `session_id`。
4. 当 Agent Host 接收需要本地工具的动作时，插件应使用会话标识校验动作来源和模型策略，并按动作协议执行本地能力。
5. 当用户切换模型时，正在运行的动作应保留原始模型和版本信息，新动作应使用更新后的会话策略。

### 需求 11：Skills 生命周期管理

**用户故事：** 作为 Agent 会话用户，我希望在任一 Agent 工作台上传和管理 Skills，使 Agent 可以复用项目级工作流和工具规则。

#### 验收标准

1. 当用户上传 Skill 时，系统应校验名称、分类、内容格式、版本和权限，并返回唯一 Skill 标识。
2. 当用户启用 Skill 时，系统应将 Skill 版本绑定到指定用户、项目或 Agent 会话范围。
3. 当 Agent 选择 Skill 执行本地动作时，云端应向插件发送 Skill 标识、版本、能力声明和最小必要内容。
4. 当插件接收 Skill 时，插件应校验来源、版本、能力范围和本地执行策略，再允许 Skill 触发工具动作。
5. 当用户禁用或撤销 Skill 时，云端应阻止新动作使用该 Skill，并向已连接插件发送撤销事件。

### 需求 12：统一本地执行策略与验证开关

**用户故事：** 作为 Agent 会话用户，我希望在当前 Agent 工作台统一控制本地执行和验证行为，使执行过程符合我的授权意愿。

#### 验收标准

1. 当用户打开或关闭本地执行总开关时，云端应将策略版本同步到关联插件。
2. 当用户配置验证类型开关时，系统应分别控制 `syntax_check`、`dependency_check`、`build`、`unit_test`、`e2e_test` 和 `service_check` 动作。
3. 当用户选择自动执行、逐次确认或失败后确认策略时，插件应按照最新策略处理对应动作。
4. 当动作涉及文件修改、依赖安装、服务启动或网络访问时，系统应按照风险规则请求审批并记录审批结果。
5. 当本地执行总开关关闭时，插件应暂停新的工具动作，并将原因和策略版本回传网页端。

### 需求 13：单工作台用户体验

**用户故事：** 作为 Agent 会话用户，我希望在当前 Agent 工作台完成控制、审批和结果查看，使本地执行过程保持在当前 Agent 会话中。

#### 验收标准

1. 当 VS Code 工作台连接云端会话时，工作台应展示扩展连接状态、工作区名称和能力清单。
2. 当 Agent 需要用户决策时，当前工作台应展示动作影响、目标、命令摘要、风险和可用操作。
3. 当用户在任一工作台批准或拒绝动作时，系统应将决策关联到动作、会话、策略版本和用户标识。
4. 当扩展产生日志、诊断或验证结果时，当前工作台应在 Agent 会话中按时间顺序展示。
5. 当 VS Code 工作台暂时离线时，系统应显示离线状态、待处理动作和恢复后的同步结果。

### 需求 14：安全、权限与审计

**用户故事：** 作为平台管理员，我希望本地 Agent Host 的能力可限制、可审计和可撤销，使网页 Agent 的本地权限处于可控范围。

#### 验收标准

1. 当插件连接网页端时，系统应使用短期会话凭据和工作区绑定校验连接身份。
2. 当插件执行文件、终端、网络或进程动作时，系统应根据动作类型和策略进行权限判定。
3. 当用户批准高风险动作时，系统应记录用户、动作、策略版本、时间、工作区和结果摘要。
4. 当用户撤销会话或工作区授权时，插件应停止未开始的动作并使旧凭据失效。
5. 当插件回传事件时，系统应过滤凭据、完整环境变量和不必要的源码内容。

## 5. 约束与非功能要求

- 插件只访问项目开发者授权的工作区和会话策略允许的资源。
- Web 和 VS Code 是共享会话的两个 Agent 工作台，当前工作台承担即时控制面。
- VS Code 扩展是本地 Agent Host，负责工具动作执行、诊断采集和事件回传。
- 云端只把 `cloud_syntax` 作为云端验证结果；本地构建、依赖安装、单元测试和 E2E 结果必须使用本地验证范围。
- 验证动作、结果和事件必须支持 `event_id` 幂等、`revision` 冲突检测和 `sequence` 顺序恢复。
- 本地命令必须具备可配置超时、可取消能力和资源限制。
- 结果回传采用最小必要数据原则，完整源码、密钥和完整环境变量保留在本地。
- 插件 E2E 验收覆盖真实 VS Code 工作区、本地依赖、失败重试和断线恢复。

## 6. 当前基线

- `app/agent/nodes/validation.py` 已提供云端验证和本地动作创建基础。
- `app/agent/local_validation_adapter.py` 已提供本地结果校验和状态合并基础。
- `app/agent/state/models.py`、`reducer.py` 和 `checkpoint.py` 已提供状态、版本和恢复契约。
- VS Code 插件当前已具备本地验证协议、执行器、结果存储和真实 Extension Host E2E 基础，完整 Agent Host 消费链尚未实现。
- 本规格对应 StateGraph 规格中的 `SG-007`、`SG-008` 和 `SG-009` 本地验证闭环。
