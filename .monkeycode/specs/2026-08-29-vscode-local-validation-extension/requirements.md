# VS Code 本地验证插件 SSD 需求文档

## 1. 引言

本规格定义 CodingMatrix VS Code 本地验证插件的产品边界、交互契约和验收要求。插件作为云端 Agent 的本地执行端，接收云端生成的验证动作，在用户本地项目环境中执行构建、依赖检查、单元测试、E2E 测试和服务级验证，并向云端回传脱敏结果。

插件只负责用户授权范围内的本地执行和结果回传。云端继续负责项目生成、状态编排、基础语法验证、任务版本管理和结果聚合。

## 2. 术语表

- **插件**：运行在 VS Code 中的 CodingMatrix 本地验证扩展。
- **云端**：CodingMatrix FastAPI 服务及其 Agent、StateGraph 和验证节点。
- **验证动作**：云端写入 `State.pending_actions`、等待插件执行的结构化任务。
- **本地验证范围**：`local_runtime` 或 `local_e2e`。
- **云端验证范围**：`cloud_syntax`，表示云端基础语法和结构检查。
- **验证结果**：插件对验证动作生成的脱敏结构化结果。
- **任务版本**：由 `task_id` 和 `revision` 标识的状态版本。
- **用户项目**：用户在本地工作区中授权给插件访问的项目目录。

## 3. 用户角色

- **项目开发者**：在 VS Code 中授权工作区、查看验证动作和执行结果。
- **云端 Agent**：生成验证计划、创建本地验证动作和聚合验证结果。
- **平台管理员**：配置云端验证范围和插件兼容策略。

## 4. 需求

### 需求 1：工作区授权

**用户故事：** 作为项目开发者，我希望明确授权本地项目工作区，使插件仅在授权范围内执行验证。

#### 验收标准

1. 当插件首次访问工作区时，插件应请求项目开发者确认工作区路径和访问范围。
2. 当项目开发者确认工作区后，插件应保存当前工作区标识，并将工作区标识关联到后续验证结果。
3. 当验证动作引用授权工作区之外的路径时，插件应将动作标记为 `rejected`，并返回结构化路径原因。
4. 当项目开发者撤销工作区授权时，插件应停止该工作区的待执行动作，并清除本地授权状态。

### 需求 2：验证动作接收

**用户故事：** 作为云端 Agent，我希望向插件发送带版本信息的验证动作，使插件可以执行与当前项目状态匹配的本地任务。

#### 验收标准

1. 当云端产生 `local_runtime` 或 `local_e2e` 验证动作时，插件应接收动作的 `task_id`、`session_id`、`revision`、`schema_version`、`validation_scope`、工作区标识和执行参数。
2. 当插件接收到不支持的 `schema_version` 或 `validation_scope` 时，插件应返回结构化的 `unsupported_contract` 结果。
3. 当插件接收到重复的 `event_id` 或已完成的任务版本时，插件应返回已有处理状态，并保持一次执行语义。
4. 当插件无法确认工作区或任务版本时，插件应将动作置为 `waiting_for_confirmation`，并向项目开发者展示原因。

### 需求 3：本地验证执行

**用户故事：** 作为项目开发者，我希望插件在本地真实项目环境中执行验证，使结果反映本地依赖和服务条件。

#### 验收标准

1. 当项目开发者批准 `local_runtime` 动作时，插件应按动作声明执行依赖检查、项目构建、单元测试或本地服务检查。
2. 当项目开发者批准 `local_e2e` 动作时，插件应按动作声明执行端到端测试，并记录测试框架、命令摘要和退出状态。
3. 当本地命令超过动作声明的超时时间时，插件应终止该命令，并返回 `timeout` 状态、已执行时长和脱敏诊断摘要。
4. 当本地验证命令返回非零状态时，插件应返回 `failed` 状态、退出码、失败摘要和可定位的文件或测试信息。
5. 当本地验证命令成功完成时，插件应返回 `passed` 状态，并记录验证范围、执行环境摘要和结果时间戳。

### 需求 4：敏感信息保护

**用户故事：** 作为项目开发者，我希望验证结果保护本地密钥和敏感环境信息，使云端只获得完成验证所需的信息。

#### 验收标准

1. 当插件采集命令输出、环境变量或错误信息时，插件应在上传前过滤密钥、令牌、密码、Cookie 和完整环境变量内容。
2. 当插件生成验证结果时，插件应上传摘要、hash、退出码、测试统计和诊断位置等必要信息。
3. 当插件发现结果中包含未脱敏的敏感字段时，插件应阻止结果上传，并记录本地脱敏失败原因。
4. 当云端请求执行参数包含工作区外路径、未授权网络目标或高风险命令时，插件应要求项目开发者确认并记录拒绝原因。

### 需求 5：结果回传与状态合并

**用户故事：** 作为云端 StateGraph，我希望可靠接收插件结果并合并到正确的任务版本，使最终状态可追溯且具备幂等性。

#### 验收标准

1. 当插件完成验证动作时，插件应回传 `task_id`、`session_id`、`revision`、`schema_version`、`validation_scope`、`source=local`、状态和结果摘要。
2. 当云端收到与当前 `revision` 不匹配的结果时，云端应拒绝状态合并，并返回 `revision_conflict`。
3. 当云端收到相同 `event_id` 的重复结果时，云端应保持一次状态变更，并返回幂等处理结果。
4. 当一个任务包含多个本地验证范围时，云端应在全部必需范围完成前保持 `waiting_local_validation` 状态。
5. 当所有必需验证范围通过时，云端应将任务推进到 `completed`；当任一必需范围失败时，云端应将任务推进到 `failed` 或 `partial_success`。

### 需求 6：用户交互与可观测性

**用户故事：** 作为项目开发者，我希望看到验证动作、授权请求、执行进度和结果，使本地验证过程可控。

#### 验收标准

1. 当插件收到待执行动作时，插件应在 VS Code 中展示任务名称、验证范围、目标工作区和预计影响。
2. 当验证正在执行时，插件应展示开始时间、当前阶段、已用时和可取消操作。
3. 当验证结束时，插件应展示通过、失败、超时、拒绝或等待确认状态，并提供诊断摘要。
4. 当插件连接云端失败时，插件应保留未回传结果的本地状态，并在连接恢复后按任务版本继续回传。

### 需求 7：兼容性与升级

**用户故事：** 作为平台管理员，我希望插件和云端契约能够受控升级，使历史任务保持可解释。

#### 验收标准

1. 当插件启动时，插件应检查云端支持的协议版本和插件自身版本。
2. 当协议版本不兼容时，插件应停止创建新的验证执行，并展示升级指引。
3. 当插件读取旧版本验证动作时，插件应根据声明的迁移规则转换可兼容字段或返回结构化升级错误。
4. 当插件升级后恢复未完成任务时，插件应保留原始 `task_id`、`revision` 和 `event_id`。

## 5. 约束与非功能要求

- 插件只访问项目开发者授权的工作区。
- 云端只把 `cloud_syntax` 作为云端验证结果；本地构建、依赖安装、单元测试和 E2E 结果必须使用本地验证范围。
- 验证动作、结果和事件必须支持 `event_id` 幂等、`revision` 冲突检测和 `sequence` 顺序恢复。
- 本地命令必须具备可配置超时、可取消能力和资源限制。
- 结果回传采用最小必要数据原则，完整源码、密钥和完整环境变量保留在本地。
- 插件 E2E 验收覆盖真实 VS Code 工作区、本地依赖、失败重试和断线恢复。

## 6. 当前基线

- `app/agent/nodes/validation.py` 已提供云端验证和本地动作创建基础。
- `app/agent/local_validation_adapter.py` 已提供本地结果校验和状态合并基础。
- `app/agent/state/models.py`、`reducer.py` 和 `checkpoint.py` 已提供状态、版本和恢复契约。
- VS Code 插件目录和真实插件消费链当前尚未实现。
- 本规格对应 StateGraph 规格中的 `SG-007`、`SG-008` 和 `SG-009` 本地验证闭环。
