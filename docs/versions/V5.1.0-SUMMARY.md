## 一、功能特性

### 1.1 Layer 2 语义检索增强（FAISS）

**文件**: `app/agent/vector_index.py`

**功能**：
- 使用 bce-embedding 模型（768 维）替代 Jaccard 关键词匹配
- FAISS IndexFlatIP 实现余弦相似度计算
- 支持 Top-K 语义相似项目检索

**代码示例**：
```python
from app.agent.vector_index import VectorIndex

index = VectorIndex()
await index.initialize()
similar = await index.find_similar("电商网站", top_k=5)
# 返回语义相似的领域模板，即使不包含"电商"关键词
```

**效果对比**：

| 查询 | Jaccard 结果 | FAISS 结果 |
|------|------------|-----------|
| "购物网站" | 仅匹配"购物" | 匹配"电商"、"商城"、"零售" |
| "数据看板" | 仅匹配"看板" | 匹配"仪表盘"、"统计"、"可视化" |

### 1.2 Layer 3 双模型交叉联想

**文件**: `app/agent/orchestrator_requirements/layer3_dual_model.py`

**配置**：
```bash
DUAL_MODEL_A=deepseek-r1:qwen3-8b
DUAL_MODEL_B=gpt-4o
```

**工作机制**：
1. Model A 独立推理 → 生成联想列表 A
2. Model B 独立推理 → 生成联想列表 B
3. 合并结果：
   - 重叠项目：置信度 +0.1
   - 单一模型：置信度 -5%
   - 最终取 Top-N（置信度 > 0.6）

**效果**：
- 减少单模型幻觉
- 提高联想多样性
- 置信度过滤低质量联想

### 1.3 Layer 1 跨领域加权合并

**文件**: `app/agent/orchestrator_requirements/layer1_domain_detection.py`

**功能**：
- 检测 up to 3 个相关领域
- 按相关性加权合并功能点
- 主领域权重 1.0，次领域 0.7，第三领域 0.5

**示例**：
```
需求："做一个电商网站，要有用户管理和数据看板"
检测到：
1. 电商系统 (权重 1.0)
2. 用户管理 (权重 0.7)
3. 数据分析 (权重 0.5)

合并结果：
- 商品管理 (电商 1.0)
- 订单处理 (电商 1.0)
- 用户登录 (用户管理 0.7)
- 权限控制 (用户管理 0.7)
- 销售统计 (数据分析 0.5)
- 可视化图表 (数据分析 0.5)
```

### 1.4 魔鬼代言人反向审视

**文件**: `app/agent/orchestrator_requirements/devil_advocate.py`

**功能**：
- GLM-Z1 独立审查确认的需求
- 挑战假设、识别遗漏
- 提供改进建议

**审查维度**：
1. 逻辑一致性
2. 功能完整性
3. 技术可行性
4. 用户体验
5. 安全风险

**输出示例**：
```json
{
  "approved": true,
  "issues": ["未考虑并发场景"],
  "suggestions": ["建议增加订单锁机制"],
  "risk_level": "medium"
}
```

### 1.5 需求覆盖校验

**文件**: `app/agent/orchestrator_requirements/requirement_coverage.py`

**算法**：
1. 提取原始需求的关键词（TF-IDF + 词性标注）
2. 提取功能清单的特征词
3. 计算覆盖度：匹配关键词数 / 总关键词数
4. 阈值：≥30% 视为覆盖合格

**效果**：
- 防止需求遗漏
- 提供客观覆盖度指标
- 支持迭代改进

### 1.6 帮助性反馈 + 拒绝理由追踪

**文件**: `app/agent/feedback_learner.py`

**新增字段**：
```python
class FeedbackResponse(BaseModel):
    accepted: bool
    rejection_reason: Optional[str]  # 新增：拒绝理由
    helpfulness_score: Optional[int]  # 新增：帮助性评分 (1-5)
```

**用途**：
- 拒绝理由用于改进需求理解
