## H1. AI Cloud 沙箱（aicloud.py 942 行）

### 1. 现状基线

| 模块 | 行数 | 职责 |
|------|------|------|
| `aicloud.py` | 942 | AI Cloud 沙箱：chat/read/write 各自沙箱执行、独立审查队列、audit-logs、aicloud_knowledge 知识库 |

**现状要点**
- 沙箱执行逻辑在 chat/read/write 各端点内各自实现，无统一执行入口
- 审查流程独立于 code_reviewer
- 审计日志独立于 observability/tracing

### 2. 演化目标

```
【近期】统一沙箱入口：docker_runner 唯一执行入口（P2）
  ↓
【中期】审查收敛：与 code_reviewer 统一
  ↓
【长期】平台化：审计接入 tracing，知识库接统一检索
```

### 3. 分阶段路径

**阶段一（近期）：沙箱执行统一**
- 抽取统一 `docker_runner` 入口，chat/read/write 沙箱执行收敛到同一执行器
- 验收：沙箱执行路径单一入口，行为向后兼容

**阶段二（中期）：审查与审计收敛**
- 审查队列与 code_reviewer 统一流程
- audit-logs 接入 observability/tracing
- 验收：审查走统一 reviewer，审计日志可被 tracing 串联

**阶段三（长期）：知识库接入**
- aicloud_knowledge 接入统一检索（对齐 A11 RAG）
- 验收：沙箱侧知识检索与 Agent RAG 共用链路

### 4. 风险与依赖

| 风险 | 应对 |
|------|------|
| 沙箱行为差异大，统一易破坏 | 以 docker_runner 为准收敛，保留端点级兼容适配 |
| 知识库数据迁移 | 检索层统一，数据源保留原位置 |
